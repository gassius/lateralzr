# Improve ConceptRelationships Response with Tools

## Overview

This plan enhances the ConceptRelationships feature to:

1. Use Laravel AI SDK Tools to fetch Wikipedia and Wikimedia Commons URLs
2. Change response structure from `{concept, rationale, strength}` to `{concept, shortDescription, mediaUrl, wikiUrl}`
3. Implement concept chaining (first concept relates to seed, second to first, etc.)
4. Add logging and testability to Tools
5. Update all tests to match new structure

## Architecture Changes

### Current Flow

```
User Request → Service → Agent (LLM) → Structured Response → Normalize → Return
```

### New Flow

```
User Request → Service → Agent (LLM with Tools) → Structured Response → 
  → Enrich with Tools (Wikipedia + Wikimedia) → Normalize → Return
```

## Implementation Steps

**Note**: This plan uses Laravel Artisan commands to generate boilerplate code:

- `php artisan make:tool` - Creates Tool classes with proper structure
- `php artisan make:test` - Creates test classes with TestCase base

### 1. Create Wikipedia Search Tool

**Command**: `php artisan make:tool WikipediaSearchTool`

**File**: `app/Ai/Tools/WikipediaSearchTool.php` (generated by Artisan)

- The Artisan command will create the file with the Tool interface already implemented
- Update the `description()` method to describe the tool's purpose
- Update `schema()` to accept `concept` (string, required)
- Implement `handle()` method to:
  - Use Wikipedia API: `https://en.wikipedia.org/api/rest_v1/page/summary/{concept}`
  - Return Wikipedia page URL: `https://en.wikipedia.org/wiki/{concept}`
  - Log all invocations using `Log::channel('single')->debug()`
  - Handle errors gracefully (returns empty string or null on failure)
  - Use HTTP client with timeout and error handling

### 2. Create Wikimedia Commons Search Tool

**Command**: `php artisan make:tool WikimediaCommonsSearchTool`

**File**: `app/Ai/Tools/WikimediaCommonsSearchTool.php` (generated by Artisan)

- The Artisan command will create the file with the Tool interface already implemented
- Update the `description()` method to describe the tool's purpose
- Update `schema()` to accept `concept` (string, required)
- Implement `handle()` method to:
  - Use Wikimedia Commons API: `https://commons.wikimedia.org/w/api.php`
  - Search parameters:
    - `action=query`
    - `format=json`
    - `list=search`
    - `srsearch=intitle:"{concept}" filetype:bitmap filemime:image/jpeg`
    - `srnamespace=6` (File namespace)
    - `srlimit=1`
  - Filter for Public Domain: Use `haswbstatement:P275=Q6938433` (CC0) or check license in results
  - Return Wikimedia Commons file URL: `https://commons.wikimedia.org/wiki/File:{filename}`
  - Log all invocations
  - Handle errors gracefully

### 3. Update ConceptRelationshipAgent

**File**: `app/Ai/Agents/ConceptRelationshipAgent.php`

- Add `HasTools` interface to implements clause
- Implement `tools()` method returning array of `[new WikipediaSearchTool(), new WikimediaCommonsSearchTool()]`
- Update `schema()` to only include:
  - `concept` (string, required)
  - `shortDescription` (string, required)
- Remove `rationale` and `strength` from schema
- Update `instructions()` to:
  - Request only concept name and short description from LLM
  - Explain that tools will be used to fetch URLs
  - Explain concept chaining: first concept relates to seed, second to first, etc.

### 4. Update ConceptRelationshipService

**File**: `app/Services/ConceptRelationshipService.php`

- Update `buildPrompt()` to:

  - Takes the LLM response concepts array

  - Call `enrichConceptsWithTools()` after normalizing basic structure
- Update return type docblock to reflect new structure
- Inject Tools via constructor for testability (optional, can use new instances)

## Key Implementation Details

### Wikipedia API Usage

- Endpoint: `https://en.wikipedia.org/api/rest_v1/page/summary/{concept}`
- Normalize concept name (title case, handle spaces)
- Handle redirects and disambiguation pages
- Return URL format: `https://en.wikipedia.org/wiki/{normalized_concept}`

### Wikimedia Commons API Usage

- Endpoint: `https://commons.wikimedia.org/w/api.php`
- Use search query: `intitle:"{concept}" filetype:bitmap filemime:image/jpeg`
- Filter by Public Domain using structured data: `haswbstatement:P275=Q6938433` (CC0) or check license
- Return first matching result URL: `https://commons.wikimedia.org/wiki/File:{filename}`

### Concept Chaining Logic

- Update prompt to explicitly request chaining
- First concept: "Find a concept laterally related to '{seed}'"
- Second concept: "Find a concept laterally related to '{first_concept}'"
- Continue pattern for remaining concepts

### Error Handling

- Tools should never throw exceptions
- Return empty string or null on failure
- Log errors for debugging
- Service should handle null URLs gracefully

### Testability

- Tools can be mocked in tests
- Use dependency injection or factory pattern if needed
- Smoke tests verify external API integration
- Unit tests verify logic without external calls
